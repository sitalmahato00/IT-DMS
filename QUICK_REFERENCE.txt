🔑 KEY RELATIONSHIPS
──────────────────────────────────────────────────────────────────────────

User Hierarchy:
    USERS (root)
    ├─1:1→ TEACHERS
    ├─1:1→ PARENTS → 1:Many → STUDENTS
    └─1:1→ STUDENTS

Academic Flow:
    SUBJECTS
    ├─1:Many→ SUBJECT_TEACHER ←1:Many← TEACHERS
    ├─1:Many→ SUBJECT_STUDENTS ←1:Many← STUDENTS
    ├─1:Many→ EXAMS → 1:Many → EXAM_MARKS → Many:1 ← STUDENTS
    ├─1:Many→ ATTENDANCE (Tracks STUDENTS & SUBJECTS)
    ├─1:Many→ MARKS (Tracks STUDENTS)
    ├─1:Many→ TIMETABLE_SLOTS (Tracks TEACHERS)
    ├─1:Many→ STUDY_MATERIALS
    ├─1:Many→ ELECTIVE_ENROLLMENTS (STUDENTS requests)
    └─1:Many→ NOTICES

Assessment Pipeline:
    STUDENTS → SUBJECT_STUDENTS → SUBJECTS → EXAMS → EXAM_MARKS
    MARKS (Alternative marking system)
    ATTENDANCE (Tracks class presence)

📊 DATA FLOW EXAMPLE: Student Taking Exam
──────────────────────────────────────────────────────────────────────────
1. Student enrolls in Subject (SUBJECT_STUDENTS)
2. Teacher is assigned to Subject (SUBJECT_TEACHER)
3. Exam is created for Subject (EXAMS)
4. Attendance tracked for Student-Subject (ATTENDANCE)
5. Student's exam marks recorded (EXAM_MARKS)
6. Final grade calculated (MARKS)

🔐 SECURITY FEATURES
──────────────────────────────────────────────────────────────────────────
